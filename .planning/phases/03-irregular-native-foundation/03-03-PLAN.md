<objective>
Build the two screens she actually lives in — the thirty-second check-in and the cycle view — plus
the bleed taxonomy she records through, pause mode and the regulatory notice. This is where the
irregular-native promise either becomes true or becomes marketing.

Purpose: everything upstream of this plan is computation she never sees. Two of this phase's
requirements are only half-true until this plan lands. CYCL-02 is not really a data requirement at
all; it is a requirement about the sentences on a screen, and this plan owns those sentences and the
test that keeps them honest. CYCL-04 is modelled, validated and unit-tested in plan 03-02, but a
taxonomy nobody can select from is a taxonomy that only ever records one value — so this plan also
owns the control that makes the other three bleed types reachable by a real woman.

Output: the daily-use surface of the product, with a copy lint that runs against rendered output.

Owner: Belson Johnson. Satheeshkumar reviews the copy at the checkpoint before this plan closes —
the dignity review is a gate, not a suggestion.

bleed detail control was considered as its own plan and rejected — it modifies `CheckinForm.tsx`,
which this plan owns, so a separate plan would collide on that file and be forced into wave 4,
landing the control *after* the escalation and export work in 03-07 that reads the data it produces.
