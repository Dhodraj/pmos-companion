## Decisions this plan locks

**D5-A — The crisis screen has zero network dependency, by construction.** Its copy is a
compile-time `as const` module in the app bundle. It is never fetched, never templated, never
localised at runtime. SAFE-03's "never rate-limited, never paywalled, never login-gated" is then
true because there is nothing in the render path that could be gated — not because a config was set
correctly. (RESEARCH Pitfall 3; Don't Hand-Roll "Crisis-path availability guarantee".)

**D5-B — The crisis event carries no subject identifier.** The D1 row records
`{screening_type, escalation_fired, escalation_reason, occurred_at}` and nothing else. No
`user_id`, no responses, no score, no free text. NFR-903 asks for "counts only, reviewed weekly";
counts do not require knowing whose. This also removes an irreversible privacy door: a server-side
record that a specific account had a suicidality escalation cannot be un-written once it exists.
Adding an identifier later would be an additive migration; removing one is not. (ADR-004,
NFR-901/903.)

**D5-C — The 24-hour nudge is content-free.** Title "Checking in", body "How are you doing today?".
It does not re-surface crisis resources, does not reference the escalation, and does not vary by
what triggered it. RESEARCH Open Question #3 is resolved here: a nudge whose content varies with her
state turns the notification itself into a channel that leaks that state to anyone who sees her lock
screen. There is no further automated escalation chain after this single nudge — the reviewing
clinician's instruction was that the pathway as written is the right scope and that we should not
build more than it. (CON-CLIN-05.)

**D5-D — No emergency-services number is added.** CON-CLIN-05 specifies Tele-MANAS routing and
nothing more. Adding a "call 112" line would be new crisis content beyond what the reviewing
clinician approved. It is deliberately omitted here and raised as an explicit question in Plan 06's
sign-off packet rather than shipped unreviewed.

**D5-E — CIRC-01/CIRC-02 (the support circle) are NOT in this phase.** SAFE-05 requires a fixed
prompt to contact a trusted person — one static line of copy. It does not require contact
nomination, contact storage, or notifying any third party. CIRC-01/CIRC-02 are marked "Tracked, not
in the current roadmap" in REQUIREMENTS.md and appear in no Phase 5 requirement. Any task involving
a third-party contact is out of scope for this phase. This is a recorded scope boundary, not an
oversight.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → Worker | Untrusted client payload crosses into `POST /screening-events`; the only Phase 5 write path to D1 from the crisis flow |
| on-device store → network | The boundary that ADR-004 forbids raw screening data from crossing at all |
| build → runtime (crisis copy) | The boundary that must NOT exist: crisis strings are fixed at build time, never fetched at runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Denial of Service | Crisis screen render path | critical | mitigate | Zero network dependency by construction (D5-A), enforced by `tests/crisis/no-network-imports.test.ts`; escalation renders before any network work and swallows failures (Task 2) |
| T-05-02 | Information Disclosure | `POST /screening-events` payload | critical | mitigate | Three-field `zod` contract at the Worker boundary; extra fields rejected 400; no subject identifier column exists to receive one (D5-B, Task 3 test) |
| T-05-03 | Tampering | Crisis copy strings | critical | mitigate | `as const` compile-time literals plus `tests/crisis/fixed-copy.test.ts` character-exact snapshot; no interpolation library reachable from the render path |
| T-05-04 | Information Disclosure | 24-hour nudge notification content | high | mitigate | Content-free fixed title/body (D5-C); the nudge does not vary by trigger, so a visible lock screen leaks nothing about her state |
| T-05-05 | Spoofing | Unauthenticated event POST inflating counts | medium | accept | The endpoint accepts no subject identifier and writes counts only; forged rows distort a weekly aggregate but expose no user and grant no capability. Adding auth to any part of the crisis flow would create the gating surface SAFE-03 forbids — the tolerance is deliberate. |
| T-05-06 | Repudiation | Escalation fired but no event recorded (offline) | low | accept | Recording is fire-and-forget by design; the phone number reaching her outranks the audit row. Counts under-report during outages and the weekly review reads them as a floor, not a census. |
| T-05-SC | Tampering | npm installs for this phase | high | mitigate | Task 1 blocking-human legitimacy checkpoint against the RESEARCH.md audit table before any install |
