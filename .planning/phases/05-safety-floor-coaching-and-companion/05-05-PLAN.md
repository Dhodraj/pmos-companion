<objective>
Build a companion that answers from a curated guideline corpus with visible citations, and that
cannot be talked into diagnosing her, scoring her risk or changing her dose.

Purpose: COMP-02's boundary is the kind that a system prompt cannot hold. Prompt-level instructions
work under normal conditions and fail under rephrasing, jailbreak framing and multi-turn context
manipulation — the model can be argued with. Code outside the model's context window cannot. This
plan therefore enforces the boundary in three independent layers: a pre-model intent router that
means the model is never called for a blocked question, a retrieval similarity floor that catches
rephrasings the router missed by finding no matching guideline passage, and an output-side scan that
reads the model's own answer as a backstop. No single layer is claimed to be complete; that is the
point.

Output: the Worker-side companion pipeline, the curated corpus and its Vectorize index, and the chat
surface that shows where every answer came from.

**Owners:** Dhodraj Sundaram (dhodraj) — the guardrail router, the retrieval logic, the Gemini
proxy, the output scan.
Belson Johnson (Belsonselva) — the chat surface and the citation chips.
Satheeshkumar (SatheeshKumarSSK) — grows the adversarial rephrasing corpus and carries the refusal
copy into Plan 06's sign-off packet.
</objective>

## Decisions this plan locks

**D5-S — Three independent refusal layers, none of which is claimed to be complete.** Layer one is a
pre-model intent router in the Worker: a matched question returns fixed text and the model is never
invoked. Layer two is the retrieval similarity floor: a rephrasing that slips past layer one still
finds no guideline passage above threshold and routes to the same fixed text. Layer three is an
output-side scan of the model's own answer before it reaches the client. A keyword list is
inherently incomplete against a creatively-worded population; treating the router as finished the
day it ships is the documented failure mode.

**D5-T — The fixed referral text.** One literal serves both the blocked-intent and the no-match
cases, because from her side both mean the same thing:

`This is something to discuss with your doctor. I can share what the guidelines say in general, but I can't tell you what applies to you specifically.`

It lives in `worker/guardrail/refusalCopy.ts` as a compile-time constant. It is not crisis-path text
and does not live in the crisis copy module, but it is fixed for the same reason and goes into Plan
06's sign-off packet.

**D5-U — Gemini is never given a capability it must not use.** No function-calling tool, no
structured-output schema, and no prompt field exists anywhere in this pipeline that could carry a
score, a likelihood, a diagnosis or a dose. The strongest guarantee against the model using a
capability it should not have is that capability not existing in its reachable surface. The model
receives retrieved guideline text and a question, and returns prose.

**D5-V — The Gemini model name is resolved at implementation time, not from this plan.** The model
lineup turned over repeatedly in the months before this phase and the 2.5 family retires inside this
build window. Read the current model list from the official model documentation at implementation
time and record the chosen model string in the plan SUMMARY. Do not carry a model name forward from
the research document.

**D5-W — No screening response, score, symptom or log entry is ever included in a companion
request.** The companion receives her typed question and nothing else. It has no access to her data,
which is also why it cannot compute anything about her even if asked (ADR-004, CON-BUILD-03).

**D5-X — Corpus entries satisfy the graded-claim contract from Plan 03.** Every corpus chunk carries
an evidence grade, a review date and a source, so a cited companion answer is graded on the same
terms as a micro-action card (COACH-02 applies to every health claim, not only to the coaching deck).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Worker `/companion/ask` | Untrusted free-text question, the primary injection surface in this phase |
| Worker → Gemini | The only path to a model; the key lives here and must not cross back toward the client |
| model output → client | Untrusted generated text crossing to a user in a health context |
| corpus → answer | Curated content becomes a cited claim; citation trust depends on citations coming from retrieval, not from generation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-25 | Tampering | Prompt injection or jailbreak extracting a diagnosis, risk score or dose | critical | mitigate | Three independent layers (D5-S): pre-model router with a 30-plus adversarial regression suite, retrieval similarity floor, and `scanAnswer` output-side backstop |
| T-05-26 | Elevation of Privilege | The model gaining a scoring, dosing or data-access capability through tools or structured output | critical | mitigate | D5-U — no tool declaration, function declaration or output schema exists in the pipeline; asserted by the Task 1 acceptance criteria |
