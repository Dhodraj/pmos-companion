<objective>
Ring 3: the irregular-native cycle view — a timeline, an interval distribution, and a bleeds-per-year
count, all read against her own history rather than a twenty-eight-day assumption.

Purpose: HACK-06 is ring 3, and it is the screen that carries the product's framing on stage. Her
period app assumes a 28-day cycle and tells her she is late until she deletes it; this view treats the
irregularity as the signal. The copy constraint is absolute and comes from CYCL-02: no "late", no
"overdue", no "missed", no single due-date, no pregnancy-scare prompt. Those are the specific harms
that make her delete the app, and they are not softened by tone.

This is also cut-list item 4 — the last thing to go and the only one that degrades rather than
disappears. Build the degradation in now, as a prop, so applying the cut at H28 is one line rather
than a decision under pressure.

Output: a cycle view that describes an irregular cycle as a range, and a list mode one flag away.

Owner: **Belson Johnson** for `src/app/**` and `src/ui/**`. `src/core/cycle/` is Dhodraj's directory
and he writes the interval statistics; Belson consumes them (build-plan.md §2).

**If the H16 gate in plan 02-07 was called a fail, this plan is cut on the spot.** Build-plan.md §9:
"If not, the cycle view is cut on the spot to buy the hours back." Check the H16 decision in
`02-07-SUMMARY.md` before starting.

    - `bleedsPerYear` scales from the observed span, so four runs across 131 days reports roughly 11,

    - `currentDayCount(entries, today)` returns the days since the most recent bleed run started, plus
      her own percentile position within her historical intervals.
    - With one bleed run only, `cycleIntervals` returns an empty interval array and
      `currentDayCount` returns the day count with a null percentile — one cycle is not a
      distribution, and saying so is the honest output.
    - With zero bleed runs, both return empty/null and neither throws.
    - No function in this module returns anything named or derived from a fixed 28-day assumption; a
      test asserts the output for a 52-day history contains no reference to 28.

    `src/core/cycle/intervals.ts` — export `cycleIntervals(entries: LogEntry[]): { runs: Array<{start:

    number|null; maxDays: number|null; bleedsPerYear: number }` and `currentDayCount(entries, today:
    string): { days: number; percentileInOwnRange: number|null; rangeLow: number|null; rangeHigh:

    cycles in should be told the app is still learning her range, not shown a confident band derived
    from two numbers.
