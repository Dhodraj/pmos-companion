<objective>
Layer the Cloudflare enhancement tier on top of a spine that already works without it: a Hono Worker
with a D1 backing store and a Gemini phrasing proxy, reached through a client that gives up silently
and never blocks a render.

Purpose: the architecture decision in plan 02-02 made D1, the Worker and Gemini an enhancement, never
a dependency. This plan builds that enhancement and proves the boundary holds — the same tests that
passed in wave 2 must still pass with `fetch` stubbed to reject. CON-BUILD-03 constrains what Gemini
is allowed to be: it phrases a finding the engine already computed, preserving the uncertainty; it
never computes a pattern, scores a risk or suggests a dose. Build-plan.md's own risk register reaches
the same conclusion from the other direction — "Gemini quota or latency → pre-generated phrasing on
the demo path. The engine is what we are showing, not the wording."

The H16 gate closes this plan: a finding produced by the engine renders on a real screen from a real
check-in. If it does not, build-plan.md §9 says the cycle view is cut on the spot to buy the hours
back — which is plan 02-09.

Output: the Worker deployed, the phrasing path working when reachable and invisible when not, and the
H16 gate decision.

Owners: **Dhodraj Sundaram** — `worker/**` and `src/core/net/**` are his (build-plan.md §2).
**Satheeshkumar** pairs on the D1 migrations and the prompt wiring, which is his H10–H16 assignment.
Neither touches `src/app/` or `src/ui/`; the card already accepts the phrasing as a prop from plan 02-05.
</objective>

    `worker/validate.ts` — `parseFinding(input: unknown): Finding` and `parseLogEntries(input:
    unknown): LogEntry[]`, hand-written runtime shape checks that throw a typed error naming the
    offending field. The Worker is a genuine trust boundary and anything crossing it is untrusted,
    including from our own client. Reject unknown keys rather than passing them through — an
    unexpected key reaching a prompt is the prompt-injection surface.

    `worker/gemini.ts` — `phraseFinding(env, finding): Promise<string>` calling
    `ai.models.generateContent` on `gemini-2.5-flash` with `responseMimeType: 'application/json'` and a
    `responseSchema` of `{ sentence: string }`, required. The prompt carries the finding's own numeric
    fields as JSON and one instruction: phrase this exact finding as one plain-language sentence, add
    no claim not present in the data. Never pass free text a user typed — only the parsed `Finding`.
    Read the key from `env.GEMINI_API_KEY`, a secret binding, and nowhere else. If the response fails
    to parse, throw; the caller's job is to fall back, not this function's.

    `worker/index.ts` — a Hono app with typed `Bindings = { DB: D1Database; GEMINI_API_KEY: string;
    APP_SHARED_SECRET: string }`. Two routes:
    - `POST /findings/phrase` — validates the body with `parseFinding`, calls `phraseFinding`, returns
      `{ sentence }`.
    - `POST /sync` — validates with `parseLogEntries` and upserts into D1 using
      `prepare(sql).bind(...)` parameterised statements only. Never build SQL by string concatenation.
    Both routes require an `x-app-secret` header matching `env.APP_SHARED_SECRET` and return 401
    otherwise. This is not real authentication and does not pretend to be; it keeps the endpoints from
    being an open write surface to D1 for arbitrary internet callers, which at this scale is the
    proportionate control.

    `worker/migrations/0001_init.sql` — tables `log_entries` (id primary key, ts, day_key,
    cycle_phase, dimension, value, source) and `findings` (id, pair_a, pair_b, status, lag_days,
    direction, strength, observation_count, band_lo, band_hi, computed_at), applied through
    `npx wrangler d1 migrations apply`. Do not hand-roll a migrations table; wrangler tracks its own.

    `wrangler.toml` — the D1 binding and compatibility date. No secret value appears in this file, ever.

    Deploy and confirm the routes answer.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Worker | Untrusted request bodies reach D1 and a model prompt |
| Worker → Gemini | Data crosses to a third party; the key lives here |
| Worker → D1 | Persistent store reachable from the internet through the Worker |
| repo → GitHub | Repo visibility unresolved (OPEN-12); secrets must never be committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-32 | Information Disclosure | Gemini key shipped to the client | critical | mitigate | Key read only from a Worker secret binding; automated gate rejects any key assignment in `wrangler.toml`; the client never names the model |
| T-02-33 | Tampering | Prompt injection via user text reaching the model | high | mitigate | `parseFinding` rejects unknown keys; only parsed numeric fields are passed; `responseSchema` constrains the reply to `{ sentence }` |
| T-02-34 | Tampering | SQL injection into D1 | high | mitigate | `prepare().bind()` parameterised statements only; automated gate rejects interpolated SQL template literals |
| T-02-35 | Elevation of Privilege | Unauthenticated writes to D1 from a spoofed client | high | mitigate | `x-app-secret` header required on both routes, 401 otherwise |
| T-02-36 | Denial of Service | Gemini latency or quota blanking the insight card during the demo | high | mitigate | Template sentence rendered first; `requestPhrasing` bounded by a 3500ms `AbortController` and resolves null on every failure path |
| T-02-37 | Spoofing | Gemini asserting a claim the engine did not find | critical | mitigate | Prompt carries only the finding's fields and forbids added claims; schema-constrained single-string reply; the numeric claim on the card comes from the Finding, never from the sentence |
| T-02-38 | Information Disclosure | Health rows synced without consent | high | transfer | `/sync` exists but is not called from the ring 1 spine this weekend; per-class consent is PRIV-01, Phase 3. Recorded so it is not switched on by accident |
</threat_model>
