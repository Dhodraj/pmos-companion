Ring 5, optional: capture a printed lab report with the camera, recognise its text on the device, and
let her confirm each value before anything is saved.

Purpose: HACK-09 is ring 5 and build-plan.md §2 gives it no owner on purpose — "it happens only if
the hour-22 checkpoint passes early, and it is the first thing cut." §12's risk row is blunter still:
if lab OCR eats Sunday, "it was optional. Drop it without discussion."

**Do not start this plan unless the H22 gate in `02-10-SUMMARY.md` passed and there is genuine slack.**
If in doubt, do not start it. Nothing else in the phase depends on it, and starting it is how a
weekend loses its last six hours.

The research turned up a hard fact that changes how this is built: the obvious community npm package
for ML Kit text recognition requires Capacitor 8 as a peer dependency and has never shipped for
Capacitor 6. It cannot be used against the locked ADR-001 stack. The correct path is a small custom
Capacitor plugin calling Google's native ML Kit Android SDK directly through Gradle — which is what
PROJECT.md's architecture notes already call for ("native Swift and Kotlin plugins for camera, OCR and
encrypted storage"), so this is the intended implementation rather than a workaround.

  <action>
    Generate a Capacitor plugin scaffold with `npx cap plugin:generate` or add the plugin class
    directly into the app module, and register it in `MainActivity`.

    Add the Gradle dependency `com.google.mlkit:text-recognition:16.0.1` to
    `android/app/build.gradle`. This is a Maven dependency, not an npm package, and has no coupling to
    the Capacitor major version at all — which is precisely why this path works where the community
    npm plugin does not. Use the v2 API surface; v1 tutorials are stale.

    `LabOcrPlugin` exposes one method, `recognizeText({ path })`, which loads the image at the given
    file URI into an `InputImage`, runs `TextRecognition.getClient(TextRecognizerOptions.DEFAULT_OPTIONS)`
    on it, and resolves `{ blocks: [{ text, boundingBox }] }`. It runs entirely on-device; ML Kit's
    default text recognizer bundles its model and requires no network. It must not upload, cache or
    retain the image, and it must not write the recognised text anywhere — it returns it to the caller
    and forgets it.

    `src/core/labs/labOcr.ts` — a thin typed wrapper: `recognizeText(path: string):
    Promise<TextBlock[]>`, returning an empty array on any platform where the plugin is unregistered
    so the web build keeps working. No fallback to a cloud OCR service exists or may be added; ADR-004
    puts inference on the device and there is no configuration under which a lab image leaves it.

    Build and install once to confirm the plugin registers and returns blocks for a photographed page.
  </action>
