<objective>
Run the blind test: verify custody of Satheesh's sealed parameters, have the engine report what it
found on a dataset its author never chose the contents of, commit that report, and only then open
the sealed file.

Purpose: build-plan.md §1 names this as the one sentence in the pitch that cannot be faked — *the
person who wrote the engine did not know what was in the data.* Without the split, the positive
control proves nothing, because the engine author could fit to it without meaning to. This plan
exists because that claim has to be a sequence of executed steps with evidence, not an assumption
anyone makes about how the weekend went. HACK-03 calls both controls the single measurable definition
of the project working.

The negative control matters more than the positive one. Any engine can find a pattern; this one has
to be able to say there isn't one.

Output: a committed report that provably preceded the reveal, and the H10 gate decision.

Owners:
- **Satheeshkumar** — Task 1. He picked the planted pair from six candidates, rolled the lag and
  strength, ran the generator with a random seed, and holds the sealed parameter file. He is the only
  person who may open it, and only at Task 3.
- **Dhodraj Sundaram** — Task 2. He runs the engine and says out loud what it found, before anything
  is opened.
- **Both, with the team** — Task 3, the H10 gate. Dhodraj calls the branch within ten minutes.
</objective>

  <action>
    Write the protocol down before executing any of it, so the sequence is a document the team can be
    held to rather than a story told afterwards.

    `blindtest/PROTOCOL.md` — the ordered sequence, one line per step, each with its owner and the
    evidence it leaves behind:
    1. Satheesh picked the planted pair from six candidates, rolled lag and strength, ran the
       generator with a random seed. (Phase 1, HACK-02.)
    2. Satheesh sealed the parameters in a file held only by him, outside this repository. The file
       records: the planted pair, the lag in days, the strength, the designated null pair, and the seed.
    3. Satheesh hands over `blindtest/dataset.json` alone. Evidence: the custody check below passes.
    4. Dhodraj runs the engine and commits `blindtest/REPORT.md`. Evidence: the report commit sha.
    5. Only then does Satheesh open the sealed file and append the reveal. Evidence: the reveal commit
       sha, which is strictly later than the report commit sha.

    State plainly in the document that blindness requires the author not to know the parameters — it
    does not require him not to know the code. That is the version that fits the constraint and keeps
    the claim intact, and it is what the team will be asked about on stage.

    `blindtest/custody-check.mjs` — a node script that reads `blindtest/dataset.json` and exits
    non-zero if any of these hold:
    - Any row fails the frozen `LogEntry` shape.
    - Any object key anywhere in the file matches `/lag|strength|planted|null_?pair|seed|param|answer|truth/i`.
    - The file contains a top-level key other than an array of rows, or any comment-shaped string
      carrying those same words.
    - Fewer than 400 distinct `dayKey` values are present, or fewer than 8 distinct dimensions — a
      dataset too thin to test either control against is a failed hand-over, not a hard case.
    On success it prints only: row count, distinct dayKey count, date range, and the sorted list of
    distinct dimensions. Nothing per-row, and nothing that hints at which pair is which.

    Copy the handed-over dataset to `blindtest/dataset.json` and run the check. Commit both the
    protocol and the dataset in one commit, with a message naming it the hand-over.

    The sealed parameter file is never copied into this repository at any point. `.gitignore` already
    covers `blindtest/sealed-*` from plan 02-03 as a second line of defence.
  </action>
