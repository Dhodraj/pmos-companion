<objective>
Voice entry in English, transcribed on the device, with no audio leaving the phone — filling the
existing check-in form rather than replacing it.

Purpose: HACK-08, resolved in favour of the proposal (WARN-02). It is scheduled here, in Belson's
H22–H28 block, and it stays cut-list item 2 with a genuine fallback to tap-only. OPEN-13 records that
this allocation is tight, which is exactly why voice is built as a prefill on top of a check-in that
already works: cutting it removes a button, not a feature.

The constraint that needs actual verification rather than trust: both Android's `SpeechRecognizer` and
iOS's `SFSpeechRecognizer` support cloud-backed recognition, and the default is not always the
on-device path. "No audio leaves the phone" is only true if the on-device mode is explicitly requested
and the result confirmed in airplane mode on the actual demo phone. Research assumption A3 flags this
as unverifiable from documentation.

Voice survives as an input method only. Voice biomarker mood scoring is permanently out of scope —
cross-lingual transfer collapses to roughly chance and there is no Hindi or Tamil validation. Nothing
in this plan infers anything from how she sounds.

Output: a press-to-talk button that prefills the check-in, proven offline on the demo phone.

Owner: **Belson Johnson**, all three tasks. `src/core/voice/` is a shared boundary — Belson writes it
here because it is his feature and Dhodraj is on integration review only after H20 (build-plan.md §8,
H22–H28 row). **Satheeshkumar** reviews every commit in this window per build-plan.md §4.
</objective>

    `src/core/voice/speech.ts`:
    - `isOnDeviceAvailable(): Promise<boolean>` — requests permission, queries the plugin's supported

      failure this wrapper exists to prevent — the honest behaviour when on-device is unavailable is
      to disable the voice button, not to transcribe over the network.
    - The module never stores, buffers or writes audio anywhere. It handles transcripts only.

    call passes the on-device option; the returned stop function is idempotent.

      `skin_severity`, and nothing for any other dimension.
    - "Mood was okay, energy low" yields a mid `mood` and a low `energy`.
    - "I took my medication" yields `medication_taken: 1`.
    - An utterance mentioning no known dimension yields an empty result and no error.
    - A number outside a dimension's `max` is clamped to `max`, never written raw.
    - `parseUtterance` never returns a value for a dimension the utterance did not mention — silence
      is not a zero.
    - Pressing the voice button fills the form controls and does not submit; the user still presses Save.
    - The voice button renders disabled with an explanatory label when on-device recognition is unavailable.
  </behavior>
  <action>
    Tests first, then implement.

    `src/core/voice/parseUtterance.ts` — `parseUtterance(transcript: string): Partial<Record<Dimension,
    number>>`. A keyword-and-number matcher over `CHECKIN_DIMENSIONS`: each entry gets a small English
    synonym list and, for `kind: 'severity'`, a qualifier map (none/mild/okay/bad/severe → values).
    Numeric dimensions take the nearest preceding or following number word or digit. Clamp to the
    entry's `max`. Return only the dimensions actually mentioned.

    This is deliberately a matcher and not a model. It is deterministic, it can be read in one sitting,
    and every mapping it makes can be shown on stage. A model here would put generated interpretation
    between what she said and what gets logged, which is the same class of problem the crisis-path rule
    exists to prevent, in a lower-stakes place.

    Nothing infers state from voice: no pitch, no rate, no sentiment, no confidence score. The
    transcript's words map to values she could have tapped, and nothing else.

    `src/ui/VoiceButton.tsx` — press-and-hold to talk, showing the partial transcript live so she can
    see what it heard. On release, `parseUtterance` the final transcript and call an
    `onValues(values)` prop. Disabled with a plain label when `isOnDeviceAvailable()` is false. 44×44pt
    target, accessible name, and a visible recording indicator for the whole time it is listening.

    In `src/app/CheckIn.tsx`, render `VoiceButton` above the control column and wire `onValues` to
    prefill the matching controls. Do not change the submit path: Save still calls the same
    `writeCheckIn` with `source` set to `'voice'` for the dimensions voice filled and `'tap'` for the
    rest. One write path, two input methods.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| microphone → recognizer | Raw audio; the claim is that it never crosses off-device |
| transcript → logged values | Spoken words become entries the engine correlates on |
| plugin → OS recognizer | A third-party wrapper over an OEM-variable platform service |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-59 | Information Disclosure | Audio silently transcribed by a cloud recognizer | critical | mitigate | On-device option passed explicitly; `startListening` refuses when unavailable; airplane-mode verification on the actual demo phone is the acceptance test, not the README |
| T-02-60 | Information Disclosure | Audio persisted to disk | high | mitigate | Automated gate rejects any filesystem, Blob or MediaRecorder reference in `src/core/voice/`; the module handles transcripts only |
| T-02-61 | Tampering | A model interpreting what she meant between speech and log | high | mitigate | Deterministic keyword-and-number matcher; automated gate rejects any model client or sentiment/prosody reference |
| T-02-62 | Repudiation | Voice used to infer mood as a biomarker | critical | mitigate | Permanently out of scope; nothing derives a value from pitch, rate or sentiment, asserted by the same gate |
| T-02-63 | Tampering | A second write path diverging from the tap path | high | mitigate | Voice prefills form state only; Save calls the one `writeCheckIn`; automated gate rejects direct Dexie writes in `CheckIn.tsx` |
| T-02-64 | Elevation of Privilege | Microphone permission requested without a visible indicator | medium | mitigate | Recording indicator visible for the entire listening window; capture is press-and-hold, foreground and user-initiated (ADR-002) |
</threat_model>
