<objective>
Build the two screens a capture ends on, the one decision that determines whether the feature exists
on this phone at all, and the wiring that makes the live capture flow actually use any of it: the
failure state with reason-specific guidance, the result screen showing a range with a confidence, a
capability-gated entry point that renders nothing when the answer is anything other than a clear yes,
and the four call sites that connect capture completion to the real pipeline, to these two screens,
and to persistence.

Purpose: failure is the normal case in this feature — that is a stated project constraint, not a
concession — so the failure screen is not an edge case, it is a primary screen and gets built like
one. And the result screen is where the phase's central discipline lives: she gets a range with a
confidence, never a single precise digit, because a precise digit is a claim this pipeline cannot
support and a fixation object for a population with roughly six times baseline anxiety.

Task 4 exists because every other thing in this phase can be finished, tested and reviewed while the
app still runs the tracer. Plan 06-01 shipped a deliberately dependency-free coarse estimator so the
architecture could be proven end to end before the mathematics existed, and Plan 06-06 built the real
cross-checked pipeline with its quality gate and its confidence. Until the completion path calls the
second one, the feature a user gets is the first one — and the two screens built here render for
nobody. Wiring is not a formality at the end of the plan; it is the difference between a phase that
shipped and a phase that compiled.

Why this plan sits in Wave 5: Tasks 1 to 3 need only the frozen types from Plan 06-01 and the copy
tone from Plan 06-05, but Task 4's whole point is that its call sites are real, so it cannot run
before `analyzeCapture` (Plan 06-06) and the measurement store (Plan 06-08) exist as modules that can
genuinely be imported and called.

Output: three components, two copy modules, a feature that is invisible where it cannot work, and a
capture flow that runs the validated pipeline and stores what it accepts.
</objective>
