<objective>
Prove the whole Phase 6 architecture end to end on one Android phone before any layer is built out:
finger on the rear camera with the torch lit, locked exposure, red-channel means over the bridge, a
coarse heart rate in TypeScript, a range on screen. One path only. Then freeze the two interface
contracts (the plugin's `definitions.ts` and the feature's `PPGResult`) so Waves 2 and 3 can run in
parallel against them, and stand up the test harness and synthetic fixtures every later DSP task
needs.

Purpose: the riskiest unknown in this phase is not the signal maths — the PRD already specifies it
(FR-301) — it is whether a hand-written Capacitor 6 native plugin can hold a locked-exposure,
torch-lit camera session on a budget Android phone at all. Finding that out after one commit is
cheap. Finding it out after the DSP pipeline, four screens and a device fleet matrix are built is
not.

Output: a working single-path capture on real hardware, two frozen interfaces, and a green test
harness with fixtures.
</objective>

Freeze two interfaces in this task, fully, even though only one branch of each is implemented here:

`packages/capacitor-plugin-ppg-camera/src/definitions.ts` declares `checkCapability()`,
`startCapture(options)`, `stopCapture()`, and an emitted per-frame sample event carrying a single
float plus a monotonic frame index. The capability method's return type is a discriminated union
with a supported branch and an unsupported branch carrying a reason (missing torch, missing camera,
exposure lock unavailable, probe failed). Declare it here; Plan 06-04 implements it.

`src/features/camera-vitals/types.ts` declares `PPGResult` as a discriminated union on a status
field: an accepted branch carrying a low bound, a high bound and a confidence level of low, medium
or high; a rejected branch carrying a machine-readable reason of saturated, motion, weak AC/DC
ratio, or capture interrupted; and an unsupported branch. There is deliberately no scalar
heart-rate field anywhere in this type — a component that tries to render one must fail to compile.
This mirrors the frozen finding type from Phase 1, where "not enough data" is a value of the type,
not a special case written at three in the morning.

Implement the Android path only, one call site, no batching, real error handling on that single
path. In `PpgCameraPlugin.kt`, bind a CameraX `ImageAnalysis` use case on the rear camera with
`setOutputImageFormat(ImageAnalysis.OUTPUT_IMAGE_FORMAT_RGBA_8888)` and a target frame rate of 30 —
request RGBA output rather than converting YUV_420_888 planes by hand. Before analysis starts, use
`Camera2Interop.Extender` to set `CONTROL_AE_LOCK` and `CONTROL_AWB_LOCK` true and `FLASH_MODE` to
torch, and lock focus. In the analyzer, compute the spatial mean of the red channel across the frame
and release the `ImageProxy` immediately in the same iteration — never accumulate pixel arrays,
never retain a buffer past the loop, never hold a reference to the raw frame outside the analyzer.

Discard the first 30 analyzed frames before emitting anything to JavaScript. This is mandatory, not
an optimisation: Apple and Android hardware alike are documented as continuing to adjust exposure
for roughly the first second after a lock call, and the resulting over-saturated frames poison the
front of the signal. Implement it as an explicit counter in the native layer so the JavaScript side
receives only post-settling samples and cannot forget to trim them.

Emit each surviving sample across the bridge as a float. Nothing else crosses the bridge — no
preview frame, no thumbnail, no encoded image payload of any kind, not even behind a debug flag. The
finger covers the lens, so there is no preview worth showing and no reason to ship one.

On the TypeScript side, `pipeline/bpm-coarse.ts` takes the collected sample array plus the sample
rate and returns a `PPGResult`. For the tracer, estimate the dominant frequency by mean-removal and
counting positive-going zero crossings inside the 0.7–3.5 Hz plausibility window, then widen it into
a range of at least plus or minus 5 beats per minute and label the confidence low. Do not pull in an
FFT library or design a Butterworth filter here — Plans 06-03 and 06-06 own that, and the tracer
must stay dependency-free so the architecture is what is being tested, not the maths. Reject with
the capture-interrupted reason if fewer than 600 samples arrived.

`capture-screen.tsx` is the thinnest possible screen: a start button, a 30-second countdown, and on
completion the accepted branch rendered as "a low to high band, confidence low" or the rejected
branch rendered as its reason. No styling polish, no waveform, no guidance copy — Plans 06-05 and
06-07 build all of that out from this proven slice.

Write `PpgCaptureInstrumentedTest.kt` as a connected-device instrumented test that starts a capture,
runs it for 5 seconds, and asserts: samples were received, the count is consistent with 30fps minus
the discarded warm-up window, every sample is finite and inside the valid 8-bit channel-mean range,
and the emitted frame index of the first sample proves the warm-up frames were dropped.

Author `fixtures.ts` as generated, deterministic, in-repo synthetic signals, each exported with its
declared ground truth alongside it so tests assert against a stated expectation rather than a magic
number. Generate at a 30 Hz sample rate and 900 samples (30 seconds) unless noted:

- A clean signal: a sine at a known rate inside the plausible band, on a realistic DC offset, with a
  slow linear baseline drift superimposed so the detrending step has something real to remove.
- A second clean signal at a different known rate near the top of the band, to catch an estimator
  that has been accidentally tuned to one frequency.
- Pure Gaussian noise with no periodic component — the null control. Any estimator that returns a
  confident rate on this fixture is broken, exactly as the project's own blind-test philosophy
  demands of the correlation engine.
- A saturated fixture: channel means clipped at the top of the 8-bit range for a large fraction of
  the window, as a finger pressed hard enough to occlude the capillary bed or a torch reflecting off
  a nail produces.
- A motion fixture: the clean signal with large aperiodic step excursions injected at intervals.
- A weak AC/DC fixture: the clean signal with its pulsatile amplitude scaled down to a fraction of a
  percent of its DC level, as cold hands or a partly-covered lens produce.
- A short fixture: fewer samples than a 30-second capture yields, for the interrupted-capture path.
- A warm-up-contaminated fixture: the clean signal with its first 30 samples replaced by saturated
  values, so the discard window is testable from the TypeScript side too.

Write `scripts/generate-butterworth-reference.py` to emit `butterworth-reference.json` containing
the numerator and denominator coefficients of a fourth-order Butterworth bandpass at 0.7–3.5 Hz for
a 30 Hz sample rate, produced by `scipy.signal.butter`, together with the impulse response of that
filter applied to the clean fixture. Run it once, commit the JSON output, and record in the fixtures
README that the JSON is the checked-in oracle and the script is how it was produced. Plan 06-03
cross-validates its hand-implemented filter against this file rather than trusting a fresh
derivation — filter design has stability and gain-normalisation failure modes that look right and
are wrong. Do not add the third-party filter-design package the research pass flagged as suspicious;
it declares no repository and is effectively unmaintained, and adopting it would require a blocking
human legitimacy check that this approach avoids entirely.

`fixtures.test.ts` asserts the fixtures themselves are what they claim: correct lengths, declared
ground-truth rates recoverable from the generator parameters, the saturated fixture actually
clipping, the weak-AC/DC fixture's ratio actually below the threshold it is meant to trip, and the
reference JSON parsing with the expected coefficient array shapes.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Camera hardware → native plugin | Raw pixel buffers enter process memory; they must be reduced to a scalar and released inside the analyzer loop |
| Native plugin → JavaScript bridge | The only sanctioned payload is a numeric array; anything richer is an information-disclosure surface |
| npm registry → build | Package-manager installs pull third-party code into the native build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Information Disclosure | `PpgCameraPlugin.kt` analyzer loop | high | mitigate | Compute the red-channel mean and call `close()` on the `ImageProxy` in the same iteration; never store frames in a field, list, or cache. Verified by code review plus the instrumented test asserting only scalars are emitted. |
| T-06-02 | Information Disclosure | Capacitor bridge surface (`definitions.ts`) | high | mitigate | The declared interface carries floats only; the acceptance grep for base64/Bitmap/ByteArray/JSArray in the definitions file is a standing gate against a debug-time regression. |
| T-06-03 | Tampering | Coarse estimator on the null fixture | medium | mitigate | The tracer estimator must reject rather than invent a rate when the sample count is short; the null-control fixture from Task 2 makes a confident answer on noise a test failure from Wave 1 onward. |
| T-06-04 | Denial of Service | Camera session acquisition | medium | mitigate | Handle a failed or lost session with the capture-interrupted rejected branch and a clean teardown, never an uncaught exception. |
| T-06-SC | Tampering | npm/Gradle installs (`@capacitor/core@6`, `@capacitor/cli@6`) | high | mitigate | Research's Package Legitimacy Audit covers both; the `too-new` flag on Capacitor is a documented mechanical false positive on this project's own already-locked framework, so no human checkpoint is required here, but the version pin is asserted in the automated verify and `fili` (genuinely SUS) is blocked from `package.json` by an automated check. |
